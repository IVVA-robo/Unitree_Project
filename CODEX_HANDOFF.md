Новый чат должен иметь доступ к репозиторию/клону. Одна ссылка сама по себе
не передаёт SSH-доступ, секреты, подключённое оборудование и гигабайты LFS.

## Цель пользователя

Полностью автономное управление без Wi-Fi и интернета:
Pico USB-C ↔ ноутбук Ethernet ↔ R1. Сохранить нынешнюю рабочую версию,
максимально надёжные кнопки и быстрое переключение режимов, понятные подсказки
перед любым действием оператора. Последняя задача — перенести все относящиеся
к роботу материалы в GitHub и сохранить контекст для продолжения в новом чате.

Пользователь плохо понимает озвучку: **только письменные инструкции**.
Он сам умеет нажимать RUN/LOCK/СТОЙКА; предупреждать заранее.
Фраза «продолжай без робота» разрешает программную работу, не физические команды.

## Что реально собрано

- Ноутбук: Ubuntu 22.04, ROS 2 Humble, активный проект
  /home/unitree/Unitree_Project/R1_Teleoperation.
- Pico 4 Ultra / Android 14, два контроллера; APK с R1UsbPoseTransport.
- USB-владелец и локальный relay получают позы/кнопки; ROS использует их для
  IK, головы/рук и ходьбы. Для ходьбы нужен корректный grip, не только стик.
- Ethernet SDK/DDS связывает ноутбук с контроллером .161.
- Реальная камера → video hub → MJPEG/HTTP → USB reverse → Pico.
  scrcpy отдельно зеркалит доступный Android-дисплей.
- PC2 .164 использовался для дополнительных сервисов, в том числе voice;
  его текущие исходники нужно прочитать на самом PC2, не угадывать по ноутбуку.

Подробные адреса, зависимости и режимы — в README. Системные ярлыки и unit-файлы
скопированы в Deployment/Laptop как данные; не устанавливать их автоматически.

## Что проверено, а что нельзя обещать

- Зафиксированы полноценные физические RUN/LOCK без Wi-Fi.
- Полные переходы RUN → СТОЙКА и холодный запуск не стали «за секунду».
  Последний сопоставимый static start занимает `10,460 s`; старые замеры
  около 25–79 с относятся к прежним версиям и другим условиям. Новый cold RUN
  с единым observer физически завершился примерно за `36 s`; это не обещание
  одинакового времени после каждого аппаратного старта.
- По отчётам были прогоны 380, 382 и 461 программных тестов.
  Это исторические результаты соответствующих версий, не новый прогон
  всего текущего дерева во время публикации.
- Для текущего warmup-изменения действительно выполнен новый полный прогон:
  `450 passed, 5 skipped in 52.69s` в отдельном user+network namespace только
  с loopback, ROS domain 231 и закрытым actuation.
- Потеря приложения/сон очков проверялись; физическое выдёргивание кабеля
  во время движения не объявлять успешно пройденным.
- Периодические JPEG-ошибки не доказаны полностью устранёнными.
- Автокэш, static HMAC-readiness и единый prepare-клиент программно и
  поэтапно физически проверены. Не сокращать обязательный 2,25-секундный
  ArmSdk traffic gate и reader/writer проверки ради дальнейшего ускорения.
- Cold-start после перезагрузки выявил две разные задержки. Периодическое окно
  без warmup-cache устранено и cached-СТОЙКА физически проверена за `11,652 s`.
  Последовательные control readers объединены; физический cold RUN показал
  `ready_control=5,725 s`, `prepare=22,917 s` и стабильные FSM 4/811.
- Логи, PID, last-ready и state.json устаревают. На момент передачи оператор
  сообщил, что PC2 не удаётся включить. Это не доказывает отключение управляющего
  компьютера .161 или моторов; на ноутбуке могли оставаться живые процессы.
  Никакой старый LOCK/ready не является доказательством текущего физического
  состояния. Перенос файлов не выключал робота и не останавливал службы.

## Рекомендуемый следующий порядок

1. Читать TRANSFER_STATUS; проверить Git/LFS и отсутствие незавершённой загрузки.
2. Копирование PC2 заблокировано невозможностью включения. Диагностику/ремонт
   согласовать отдельно, не выполнять автоматически разборку, сброс или
   переустановку. После восстановления доступности подтвердить Ethernet/SSH .164, снять read-only
   архив Tools/GitHub/collect_robot.py в новый частный локальный каталог.
   Сначала изучить список каталогов: defaults — отправная точка, не обещание
   охвата всего диска. Добавить фактически найденные robot-related проекты.
3. Проверить архивы на секреты, сохранить права/структуру и добавить в GitHub
   фактические PC2-конфиги/исходники с отдельным README.
4. Проверить и опубликовать текущий dirty diff одним обычным коммитом без
   force-push; перед публикацией повторить secret scan, diff check и
   loopback-only regression.
5. Физические проверки СТОЙКИ, cold RUN, тёплых RUN/LOCK и обоих боковых
   направлений выполнены. Новый тест не запускать автоматически: для любой
   следующей команды снова нужны актуальный запрос и подтверждение оператора.
6. Постоянное USB-видео и исправление гонки очистки физически проверены
   несколькими СТОЙКА → RUN → LOCK при выключенном Wi-Fi. Новый физический
   запуск для этих двух исправлений не нужен. Перед публикацией проверить diff,
   секреты и тесты; не включать посторонние файлы собеседований.

## Защиты и прошлые ошибки, которые нельзя вернуть

- Не должно быть двух независимых writers/владельцев USB; writer-count=1
  остаётся обязательной проверкой.
- Нельзя запускать RUN по одной строке READY, пока worker не закончил cleanup.
- STOP/Zero Torque отменяют очередь нового движения.
- Не добавлять ExecStop=r1-exhibition stop старому USB RUN unit:
  поздний cleanup прежнего владельца может остановить новую стойку.
- Восстановление камеры не снимает LOCK/KILL/degraded.
- Нельзя автоматически продолжать ходьбу после USB-gap/потери tracking.
- Запрещён старый физический head-recenter. Не путать его с проверенной
  seed/feedback-подготовкой нового пути.
- При USB >250 мс без пакетов ходьба обнуляется, сеанс требует явного
  возобновления по штатному протоколу.
- Нельзя запускать стендовые commissioning/probe команды поверх живого RUN.
