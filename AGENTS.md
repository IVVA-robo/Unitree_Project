# Работа с Unitree R1

Перед изменениями прочитайте CODEX_HANDOFF.md, README.md и TRANSFER_STATUS.md.
Это физический робот, а не только симуляция. Сохранённый профиль панели live-enabled.

- Не запускайте RUN, StandUp/СТОЙКА, Zero Torque, writers, физические probes,
  перезапуски управляющих служб или SDK примеры без актуального запроса оператора
  и подтверждённых условий безопасности. Старые подтверждения не бессрочны.
- При задачах документации/экспорта не менять процессы, Wi-Fi, ADB-туннели,
  режим робота и установленные службы. Состояние из старого файла не доказывает
  реальное состояние железа.
- Не снимать автоматически KILL, envelope, deadman, watchdog или writer-count gate.
  Восстановление связи не разрешает движение. Не ускорять режимы сокращением
  обязательных safety-проверок.
- Общаться с оператором по-русски, короткими письменными подсказками, без голоса.
  Предупреждать заранее о нажатиях, выключении связи и любых физических тестах.
- Перед изменениями сохранять бэкап вне рабочего дерева. Существующие изменения
  принадлежат пользователю; не сбрасывать их и не перезаписывать конфигурацию вслепую.
- Активный код: R1_Teleoperation; Unity_Projects/Unitree_VR_Controller.
  Legacy_Robotics, старые README и архивы — контекст, не текущая инструкция запуска.
- Тестировать без робота в изолированной сети/ROS-домене. Не считать unit-тесты
  доказательством устойчивости/скорости реального робота.
- В GitHub не публиковать SSH-ключи, токены, пароли, частные .env, auth/session
  файлы и полный экспорт частной переписки. Перед публикацией проверять архивы.
- Файлы PC2 ещё не собраны. Не выдавать локальную копию за образ робота.
- Большие бинарные файлы — Git LFS. Для готовых артефактов проверять SHA256SUMS.
  Исторические архивы сначала распаковывать в новый каталог, не поверх проекта.
