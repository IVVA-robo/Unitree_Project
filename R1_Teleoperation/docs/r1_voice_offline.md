# Русский голосовой ассистент R1

## Установка модели

`vosk-model-small-ru-0.22.zip` скачивается с прямого URL, а не со страницы
каталога. На рабочем столе компьютера R1 скопируйте из проекта скрипт
`scripts/r1-install-vosk-ru`, затем выполните:

```bash
sudo /tmp/r1-install-vosk-ru
```

Для компьютера R1 без Интернета на ноутбуке заранее соберите пакет:

```bash
./scripts/r1-stage-voice-bundle
```

Получившийся `.cache/voice-models/r1-voice-offline-bundle.tar.gz` передайте
на компьютер R1 через SSH/NoMachine/USB. Внутри пакета уже есть проверенный ZIP;
на R1 распакуйте его и выполните команду из `README.txt` с `VOSK_RU_CACHE`.
Скрипт `r1-voice-preflight` делает только чтение и проверяет модель, Python
`vosk`, локальную Ollama-модель и systemd-службу.

Скрипт использует параллельные HTTP Range-запросы (сервер на некоторых сетях
зависает после первых 16 КБ), проверяет ZIP через `unzip -t`, проверяет каталоги
`am/`, `conf/`, `graph/` и только после этого устанавливает модель в
`/opt/R1Service/models/vosk-ru`. Уже установленная модель не перезаписывается
без явного `--replace`; старый каталог при замене переносится в backup.

Чтобы передать скрипт на компьютер R1 с ноутбука, пароль вводится вручную:

```bash
scp scripts/r1-install-vosk-ru unitree@192.168.123.164:/tmp/r1-install-vosk-ru
```

Если SSH на `.164` закрыт, скопируйте файл через общий буфер/файловый обмен
NoMachine и запустите ту же команду на удалённом рабочем столе. Адрес `.161` —
роботский DDS endpoint, а не SSH-сервер.

После установки на удалённом рабочем столе:

```bash
sudo systemctl restart robot-voice-service.service
systemctl --no-pager --full status robot-voice-service.service
journalctl -u robot-voice-service.service -n 80 --no-pager
```

## Вывод голоса через динамик R1

Рабочий режим сервиса использует штатный Unitree audio RPC и не открывает
занятое системное ALSA-устройство:

```text
R1_TTS_BACKEND=unitree_rpc
R1_UNITREE_INTERFACE=eth10
R1_TTS_VOLUME=70
R1_TTS_SPEAKER=eugene
R1_MAX_RESPONSE_WORDS=12
R1_OLLAMA_MODEL=gemma3:4b-local
```

PCM от Silero автоматически переводится из 48 кГц в моно PCM16/16 кГц,
который принимает аудиосервис R1. Признак успешного запуска в журнале:

```text
🔊 Unitree RPC audio готов (iface=eth10, volume=70)
```

`aplay` остаётся только запасным режимом (`R1_TTS_BACKEND=alsa`) для отладки
вне робота. `eugene` — мужской русский голос Silero; короткие бытовые ответы
ограничены одной фразой длиной до 12 слов.

## Активация по имени «Добрыня»

Перед передачей текста в Ollama или будущий обработчик команд сервис применяет
`WakeNameGate`. По умолчанию обрабатываются только фразы, начинающиеся с
`Добрыня`:

```text
Добрыня, как дела?       → в LLM: «как дела?»
Добрыня: включи камеру   → в обработчик команд: «включи камеру»
Как дела?                → игнорируется
Я думаю, Добрыня поможет → игнорируется
```

Сопоставление не зависит от регистра, `ё` нормализуется в `е`, а запятая,
двоеточие и другая пунктуация после имени удаляются. Не прошедшая фраза не
попадает в очередь, LLM, TTS или команды робота; в debug-журнале появляется
`ignored_no_wake_name`.

Настройки читаются из `/opt/R1Service/.env` (его подключает systemd):

```dotenv
VOICE_WAKE_NAME=Добрыня
VOICE_WAKE_ALIASES=добрыня,добрян,добрыня робот
VOICE_FOLLOWUP_WINDOW_SEC=0
```

`VOICE_WAKE_NAME` задаёт основное имя, `VOICE_WAKE_ALIASES` — список через
запятую. При значении `VOICE_FOLLOWUP_WINDOW_SEC` больше нуля фраза только
`Добрыня` открывает окно прослушивания на указанное число секунд; в это время
следующая фраза может быть без имени. Значение `0` оставляет безопасный режим,
в котором имя требуется в каждой фразе. После изменения `.env` перезапустите
сервис:

```bash
sudo systemctl restart robot-voice-service.service
journalctl -u robot-voice-service.service -f
```

Проверить фильтр без микрофона можно на ноутбуке:

```bash
./scripts/r1-wake-name-smoke "Добрыня, сколько будет 5+5?"
printf 'Как дела?\nДобрыня: кто ты?\n' | ./scripts/r1-wake-name-smoke
```

Модуль находится в `voice_assistant/wake_name_gate.py`, а тесты — в
`tests/test_wake_name_gate.py`. Для изменения имени на R1 нужно также передать
обновлённые `voice_assistant.py`, `wake_name_gate.py` и `ru_numbers.py` в
`/home/unitree/VoiceAssistant/`; текущий сервис импортирует gate из этой
директории.

## Произношение цифр

Перед Silero TTS числовые токены автоматически переводятся в русские слова,
чтобы штатный голос R1 не пытался читать цифры посимвольно. Например,
`Ответ: 1200.` произносится как «Ответ: одна тысяча двести», а `1,5` — как
«одна целая пять десятых». Преобразователь находится в
`voice_assistant/ru_numbers.py`; его smoke-тесты запускаются вместе с
`tests/test_ru_numbers.py`.

## Длина ответа

После `WakeNameGate` очищенная фраза проходит через `ResponseLengthPolicy`:

- `short` — одна короткая фраза; используется для приветствий, благодарности,
  вопросов «как дела?» и коротких команд роботу;
- `normal` — один–три предложения;
- `long` — полный понятный ответ, несколько абзацев или список.

Запросы со словами «расскажи», «объясни», «опиши», «подробнее», «почему»,
«сравни», «стих», «инструкция» и похожими автоматически получают `long`.
Команды вроде «иди вперёд» и «включи камеру» остаются `short`. Safety gates
команд выполняются раньше и не меняются этой политикой.

Настройки находятся в `/opt/R1Service/.env`:

```dotenv
VOICE_DEFAULT_RESPONSE_LENGTH=normal
VOICE_SMALLTALK_MAX_WORDS=12
VOICE_ENABLE_LENGTH_POLICY=1
VOICE_VERBOSE_KEYWORDS=расскажи,объясни,опиши,подробнее,почему,сравни
```

`VOICE_ENABLE_LENGTH_POLICY=0` отключает классификацию и использует только
`VOICE_DEFAULT_RESPONSE_LENGTH`. Новые шаблоны small-talk добавляются в
`quick_template_answer()` в `voice_assistant/response_style.py`, а новые
ключевые слова — через `VOICE_VERBOSE_KEYWORDS`. После изменения `.env`:

```bash
sudo systemctl restart robot-voice-service.service
journalctl -u robot-voice-service.service -f
```

Для mock-проверки без микрофона:

```bash
./scripts/r1-response-style-smoke "Добрыня, привет"
./scripts/r1-response-style-smoke "Добрыня, расскажи стих"
./scripts/r1-response-style-smoke "Расскажи стих"  # будет ignored wake gate
```

В debug-журнале видны исходный текст ASR, очищенный текст, выбранный стиль,
причина, а также источник ответа (`ШАБЛОН` или `НЕЙРОСЕТЬ`).

Для диалога на R1 используется локальная `gemma3:4b-local` в квантовании Q4;
она занимает примерно 2.7 ГБ памяти Ollama. Модель была перенесена на робот
заранее, поэтому после установки сеть для работы не нужна. Большая `gemma4`
8B остаётся установленной, но не используется голосовым сервисом.

Чтобы убрать задержку холодного запуска, сервис при включении прогревает
локальную модель в фоне и удерживает её в памяти 30 минут после последнего
запроса. Настройки можно изменить в `/opt/R1Service/.env`:

```dotenv
VOICE_OLLAMA_WARMUP=1
VOICE_OLLAMA_KEEP_ALIVE=30m
```

В журнале появится `🔥 Ollama прогрет`. Тайминги `[OLLAMA]` и `[TTS]` помогают
понять, какой этап задерживает конкретный ответ. Значение
`VOICE_OLLAMA_WARMUP=0` отключает прогрев, а `VOICE_OLLAMA_KEEP_ALIVE=-1`
оставляет модель загруженной до остановки Ollama (это занимает около 2.5–2.7
ГБ памяти).

## Нужен ли Интернет

После установки ассистент может работать без Интернета, если:

- Vosk-модель находится в `/opt/R1Service/models/vosk-ru`;
- Silero TTS-модель уже скачана локально;
- Ollama запущен локально и модель `qwen2.5:1.5b` уже загружена (`ollama list`);
- Unitree audio RPC доступен на локальном DDS-контуре R1.

Интернет нужен только для первоначальной загрузки этих моделей и обновлений.
Если `voice_assistant.py` обращается к облачному API или модель Ollama не
скачана, без сети соответствующий этап не заработает. Микрофон, Vosk,
локальный Ollama и Unitree audio RPC не требуют внешней сети.

## Приоритет до демонстрации

Голос можно довести полностью offline уже сейчас. Руки и Sport-ходьбу сначала
проверяем в Gazebo/dry-run; физический ArmSdk и locomotion writer остаются
заблокированы до отдельного короткого теста на роботе с E-stop, свободной зоной,
исправной телеметрией и явным подтверждением оператора.
