# Unitree R1 Панель оператора

Русскоязычная desktop-панель запускается из проекта:

```bash
cd /home/unitree/Unitree_Project/R1_Teleoperation
make operator-panel
```

На рабочем столе создан ярлык **Unitree R1 Панель оператора**. Панель использует
существующие Makefile-цели и скрипты, поэтому диагностика и safety gates остаются
общими с терминальным workflow.

## Главный выставочный экран

Для выставки запускайте `make exhibition-panel`. На первом экране остаются два
основных действия:

- **LOCK / Статичный режим** — автоматический preflight и Robot POV без управления
  руками и без VR-управления ногами; отдельный static writer выполняет
  официальный `StandUp()` и подтверждает устойчивый FSM 4, не включая FSM 811
  или `SetVelocity`;
- **RUN / Полное управление** — автоматический preflight, Robot POV и
  выставочный slow-safe teleop через существующие safety gates. Панель сама
  отправляет подтверждённую команду Run/FSM 811; телефон для выбора режима не
  нужен.

Если RUN уже запущен, а writer защёлкнул KILL, повторное нажатие **RUN**
использует живой control graph вместо полного перезапуска. Панель выполняет
общую перекалибровку и token-bound fast prepare; видео, VR bridge, reader и
writer остаются запущенными. Обычно это занимает несколько секунд. Первый
холодный старт остаётся дольше, потому что включает полный read-only SDK
preflight.

Во время **Найти и подключить** панель параллельно прогревает read-only SDK
проверку. Она не создаёт writer и не снимает KILL. Свежий результат позволяет
первому RUN не повторять минутную диагностику; изменение Ethernet, RX errors,
перезагрузка компьютера, истечение срока или появление другого writer
автоматически отменяет ускорение.

Рядом показаны короткие статусы робота, очков, контроллеров, видео и активного
режима. Все кнопки этого экрана используют один автоматический сценарий
обнаружения и восстановления: **Переподключить всё** само создаёт статический
сеанс, если владельца ещё нет, а **Перекалибровать руки** сначала поднимает
контур управления и затем запускает калибровку. Кнопка
**ZERO TORQUE / РАССЛАБИТЬ** теперь находится рядом со стойкой на главном
экране и повторена в разделе **Расширенные настройки / Сервис**. Она сохраняет
подтверждение опоры и завершает управляющие процессы перед отключением момента.

В разделе «VR и очки» доступна отдельная кнопка **Калибровать голову**. Она
только сохраняет текущую нейтраль HMD через `/r1/head/calibrate_neutral` в уже
запущенном dry-run или проверенном head-сеансе; SDK-клиент, привод и KILL latch
этим действием не затрагиваются. Смотрите прямо и держите голову неподвижно.

При первой физической активации панель один раз показывает safety-чеклист и
создаёт одноразовый commissioning token. При переключении между двумя режимами
чек-лист не повторяется: панель вызывает `exhibition-stop`, закрывает прежнюю
process group и только затем занимает единственный слот `exhibition` новым
режимом. Нажатие STOP или KILL отменяет ожидающее переключение, поэтому после
остановки новый режим сам не запустится.

В текущем выставочном `config/operator_panel.json` заданы `dry_run=false` и
`allow_live=true`. Поэтому панель разрешает запрашивать физический live-сеанс,
но только после успешного preflight и полностью отмеченного safety-чеклиста.
Если конфиг отсутствует, встроенные безопасные значения возвращаются к
`dry_run=true` и `allow_live=false`. Эти параметры можно изменить на вкладке
«Настройки» или в JSON. Панель создаёт одноразовый commissioning token и
передаёт подтверждения только выбранному live-процессу. Токен не сохраняется в
конфиге или отчёте. Deadman, KILL, feedback и остальные fail-closed проверки
по-прежнему проверяются самими скриптами.

Для установленного TP-Link USB Ethernet включён параметр
`allow_half_duplex_adapter=true`. Он передаёт
`R1_SDK_ALLOW_HALF_DUPLEX=1` всем проверкам, но действует только когда Linux
точно сообщает драйвер `cdc_ether`. Это не отключает проверки RX errors/drops,
ping, LowState, motor health, SDK, STOP/KILL или commissioning. Для другого
драйвера или ошибок интерфейса preflight по-прежнему блокирует запуск. Флаг
доступен в «Настройки» как «Разрешить half-duplex только для TP-Link
cdc_ether»; безопасное значение при отсутствии конфига — `false`.

Для live-графа панель по умолчанию использует `ROS_DOMAIN_ID=88` — это тот же
домен, который использует `r1-live-session`, VR/IK и live-writer. Не меняйте его
на `89`: `89` зарезервирован для отдельного ноутбучного dry-run и тогда VR-команды
не попадут в live-writer.

### Настройка движений

В окне **Настройки** находятся шесть ограниченных выставочных параметров. Они
сохраняются в `config/operator_panel.json` и передаются в новый control-сеанс:

- **Высота рук** (`-0,15…+0,15 м`), **вперёд/назад**
  (`-0,12…+0,08 м`) и **ширина плеч** (`0,25…0,55 м`) задают виртуальные
  плечи. Эти значения записываются только при следующей команде
  **Перекалибровать руки**; существующий файл калибровки сам не меняется.
- **Чувствительность рук** (`0,50…1,20×`) задаёт
  `body_proxy.motion_scale`. После запуска режима она действует на каждый новый
  сдвиг контроллеров и не требует повторной калибровки нейтральной позы.
- **Чувствительность поворота** (`0,10…1,00×`) может только уменьшить предел
  `0,35 рад/с`.
- **Скорость ног** (`0,10…1,00×`) может только уменьшить пределы
  `0,20 м/с` вперёд/назад и `0,12 м/с` вбок.

После изменения параметров остановите и снова запустите **Режим управления**,
чтобы новый процесс получил настройки. Для первых трёх параметров затем
выполните перекалибровку. `r1-live-session` повторно проверяет, что все числа
конечны и находятся в жёстких диапазонах, до запуска ROS-графа; увеличить
slow-safe потолки через JSON или переменные окружения нельзя.

Кнопка открытия viewer по умолчанию использует `http://127.0.0.1:8080/` для
просмотра на ноутбуке. Для VR-шлема открывайте числовой LAN-адрес, который
печатает Robot POV при запуске; `127.0.0.1` внутри шлема указывает на сам шлем.

Кнопка «Проверить всё» последовательно запускает read-only проверки сети,
Ethernet/DDS камеры, robot/VR/ROS2 status. Вывод попадает во вкладку «Логи».
Предупреждения необязательных TeleImager-портов камеры остаются видны в логах,
но сами по себе не блокируют live-gate для управления руками; сеть, робот, VR,
ROS2 и safety-проверки writer по-прежнему обязательны.
Долгие режимы не запускаются вторым экземпляром. STOP и KILL доступны сверху
всегда. STOP вызывает `make exhibition-stop`, который использует проверенный
`robot-stop`; KILL напрямую вызывает `make robot-kill`.

В верхней карточке **Realtime health** панель каждые пять секунд обновляет
только read-only snapshot: Ethernet, ping робота, VR/deadman, kill latch,
writer/feedback, видеосервис и ROS domain. Кнопка «Экспортировать отчёт» во
вкладке «Логи» сохраняет обезличенный JSON в `logs/operator-report-*.json`.
Секреты и токены в отчёт не попадают.

Live-кнопки закрыты до успешного общего preflight. Даже после открытия gate
остаются обязательными `allow_live`, выключенный dry-run, фиксированный IP
VR-шлема, ручной safety-чеклист, deadman и все safety gates writer. STOP/KILL
от этого gate не зависят. Защёлкнутый software KILL отображается в статусе, но
не мешает запустить fail-closed граф: каждый physical writer обязан стартовать
именно с KILL и может снять его только внутри `robot-prepare`.

Mono-видео R1 запускается через `pov-vr`; `Stereo video (демо)` использует
подготовленный mock stereo источник. Настоящее stereo включать можно только после
появления двух физических видеопотоков. CLI `make pov-demo` и
`make pov-stereo-demo` используют отдельные локальные порты 18080 и 18081,
поэтому не конфликтуют с offline POV на 8080; порт можно переопределить через
`R1_POV_DEMO_PORT` или `R1_POV_STEREO_DEMO_PORT`.

Для командной строки добавлены явные этапы `make arms-dry-run`,
`make legs-dry-run`, `make head-live-dry-arm`, `make head-calibrate` и
`make head-live`. Последний является физическим entry point и остаётся
fail-closed: без всех commissioning-подтверждений он завершается до создания
команд роботу. `make exhibition-full-live` — совместимое имя полного
выставочного сеанса рук и ног; HMD→голова по-прежнему запускается отдельно
через `make head-live` после отдельной проверки владения и envelope.

На текущей прошивке робот при включении сам поворачивает голову влево в
калибровочную позу. Переход в штатный Lock или Running (`Start()`, FSM 811)
возвращает её в визуальный центр; после перехода feedback показывает
`head_yaw≈0`. Это действие выполняет контроллер робота, а не панель и не VR.
Панель после перехода заново читает физический feedback и только затем передаёт
голову VR‑управлению.

## Сервисный ручной сценарий

1. Откройте ярлык **Unitree R1 Панель оператора** на рабочем столе или выполните
   `make operator-panel`.
2. На вкладке «Сеть и подключения» нажмите **Проверить всё** и дождитесь конца
   read-only диагностики. Исправьте красные ошибки; предупреждение о выключенном
   роботе допустимо, если нужен только интерфейс.
3. На вкладке «Видео глазами робота» нажмите **Запустить видео глазами робота**,
   затем **Открыть viewer в браузере**. Для проверки без робота используйте
   **Stereo video (демо)**.
4. После физической проверки положения робота откройте «Руки / ноги / teleop»
   и нажмите **Повторять движения рук из VR**. Граф запустится с KILL и ещё не
   сможет двигать руками; ноги и joystick/SetVelocity в этом режиме отсутствуют.
5. Отпустите Deadman, смотрите прямо и держите оба контроллера в удобной
   нейтральной позе. Нажмите **Калибровать руки (Deadman отпущен)** и дождитесь
   `[OK] Arm neutral was saved` в логах.
6. Не меняя нейтральную позу, зажмите Deadman и нажмите **Подготовить руки**.
   После подтверждённого `FSM=4` отпустите Deadman, затем нажмите его снова.
   Только после статуса `prepare_rearm=ready` медленно сдвиньте сначала одну
   кисть на несколько сантиметров.
7. Завершите тест кнопкой **STOP**. Кнопка сначала защёлкивает central KILL,
   затем просит writer выполнить штатный StopMove и release ArmSdk. **KILL**
   выполняет тот же приоритетный порядок аварийного отключения. После cleanup
   панель автоматически закрывает весь motion launch-граф, включая SDK-reader;
   следующий тест всегда начинается с нового preflight и свежего arm-сеанса.
8. Ноги проверяйте отдельным сеансом после успешного arm-only этапа. Полностью
   закройте Unitree Explore, чтобы его виртуальный стик и видеосессия не
   конкурировали с панелью. Нажмите **Включить движение ног** и отметьте
   отдельный пункт Run в live-чек-листе панели. Панель сама выбирает Run/FSM
   811, а writer передаёт оси
   через тот же `rt/wirelesscontroller`, который использует Unitree Explore:
   сначала робот переносит центр массы/наклоняет корпус, затем делает шаг.
9. **Полный VR teleop** запускается кнопкой **RUN / ПОЛНОЕ УПРАВЛЕНИЕ** после
   общего чек-листа. Для software-проверки без приводов используйте **Полный VR
   dry-run**.

## Безопасный автозапуск

`r1-offline-session.service` запускает только локальный bridge и video-only POV;
он не запускает `r1_live_writer`, Sport, stand или locomotion. При необходимости
панель можно добавить отдельным пользовательским сервисом:

```bash
make r1-offline-service-install
make r1-operator-panel-autostart-install
```

Первая команда устанавливает, включает и сразу запускает отдельный
`r1-offline-session.service` с offline bridge и video-only POV. Вторая команда
устанавливает, включает и сразу запускает только панель, а также запись меню и
ярлык с иконкой робота на рабочем столе. Ярлык открывает единственный экземпляр
панели, принадлежащий `r1-operator-panel.service`, поэтому повторный щелчок не
создаёт второе независимое дерево процессов.

Текущий выставочный конфиг оставляет `auto_start_bridge=true` и
`auto_start_video=true`: при открытии панели автоматически запускаются только
offline bridge и video-only POV; live-команда RUN никогда не выбирается сама.
Если отдельный `r1-offline-session.service` уже установлен, он остаётся
единственным владельцем этих портов, а панель подключается к нему через
watchdog. Не запускайте второй offline-сеанс вручную. `require_preflight: true`
оставляйте включённым.

### Автоматическое переключение VR при live-запуске

Кнопки **Руки**, **Руки + Running**, **Ноги** и **Полный teleop** теперь сами:

1. находят единственный подключённый Pico через ADB и читают его текущий
   `wlan0` IPv4;
2. записывают адрес в `ROBOT_VR_SOURCE_IP` и открывают приложение
   `Unitree R1 Telepresence`;
3. останавливают только проверенный video-only
   `r1-offline-session.service`, освобождая UDP `9090/9091`;
4. восстанавливают этот сервис после закрытия live-процесса, `STOP` и выхода
   из панели.

При нескольких ADB-устройствах задайте `R1_VR_ADB_SERIAL`. Автопоиск можно
отключить через `R1_VR_AUTO_DISCOVERY=0`; тогда используется настроенный
`ROBOT_VR_SOURCE_IP`. Произвольные процессы не завершаются: переключатель
управляет только точным совместимым user-service.

При `systemctl --user stop/restart`, завершении графической сессии или выходе
из учётной записи systemd сначала запускает отдельный `ExecStop`. Если активен
выставочный manager или точный physical live-owner из сервисного раздела,
helper ждёт штатную последовательность `disarm → robot-stop → cleanup` и только
затем разрешает закрыть группу панели.
На весь путь выделено 120 секунд; при ошибке остаётся системный SIGTERM для
всей группы как резервный путь. После изменения unit примените его без запуска
робота:

```bash
make r1-operator-panel-autostart-install
systemctl --user restart r1-operator-panel.service
```

Профили POV уже доступны в панели и CLI: `low-latency`, `balanced`, `high`,
`bad-wifi`. Viewer показывает FPS, задержку, bitrate, drop и reconnect. Для
текущего одного видеопотока статус будет **mono-to-both-eyes fallback**; два
реальных глаза появятся после настройки `ROBOT_POV_RIGHT_SOURCE` или двух ROS
camera topics.

Состояние офлайн-голоса можно проверить кнопкой **Проверить голос Добрыни** или
командой `make r1-voice-preflight`. Это read-only проверка модели ASR, Ollama,
TTS и systemd-сервиса; микрофон робота и команды движения она не включает.

Минимальный набор тестов панели и Robot POV:

```bash
python3 -m pytest -q                 # корневые smoke-тесты
make operator-panel-check
QT_QPA_PLATFORM=offscreen python3 -m pytest -q tests/test_operator_panel.py tests/test_processes.py
PYTHONPATH=ros2_ws/src/r1_robot_pov:$PYTHONPATH \
  python3 -m pytest -q ros2_ws/src/r1_robot_pov/test
make operator-panel-smoke
```

Имена ROS-тестов сделаны уникальными по пакетам, поэтому общий запуск с явными
путями больше не получает `ImportMismatchError` из-за одинаковых `test_flake8.py`.
